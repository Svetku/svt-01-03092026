# ADR 002. Запуск в Docker с самого старта

- **Статус:** принято
- **Дата:** 2026-09-10

## Контекст

Проект должен одинаково запускаться у разработчика и там, где его будут пробовать. Ставить Python и зависимости вручную на каждой машине — лишний риск «у меня не работает».

Нужно простое окружение для проверки идеи, без оркестрации и нескольких сервисов.

## Решение

С самого старта упаковываем бота в **один Docker-образ**.

- один `Dockerfile`;
- один контейнер: процесс бота с long polling;
- два равноправных запуска через `make`: `make run` без Docker и `make docker-run` в контейнере.

Kubernetes, несколько контейнеров и отдельный reverse-proxy не используем.

## Последствия

- Локальный запуск (`make run`) остаётся: Docker не обязателен, если есть Python и `uv`.
- Запуск в контейнере не зависит от того, что установлено в системе, кроме Docker.
- Секреты передаём в контейнер извне, не кладём в образ.
- Образ чуть тяжелее чистого локального запуска — это приемлемо ради повторяемости.
